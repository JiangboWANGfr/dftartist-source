原理图显示重设计:方案对比

针对三个问题:pin 名字缺失、连线"接错" pin、always/assign 大框语义不明。下面是根因、现状与重设计方案的视觉对比,以及需要你确认的几个决定。尚未改任何代码。

01三个问题的根因

①pin 名字没画

数据一直都在:get-ports 返回 busLabel,盒子宽度也按标签宽度预留了(nodeDims),但 SchematicTab 只画了菱形,从未画名字。

修法:在盒子边缘内侧渲染 busLabel,输入贴左、输出贴右。

②pin 被 ELK 重排

连线终点其实是对的 pin —— 但 FIXED_SIDE 只固定左右侧,ELK 每次重布局都会自由重排同侧 pin 顺序,把有连线的 pin 挪到顶部。你点的 pin 变灰后"跳走了",又没有名字,看起来就像依次连到前几个 pin。

修法:FIXED_ORDER + 按 RTL 声明序固定 pin 位置,永不重排。

③always 框 = 行为级驱动源

fanin 找不到同层实例时,daemon 用 slang 分析找到真正驱动:父模块里的 always/assign/输入端口。现在画成和模块一样大的棕框,标题副标题重复,也不显示驱动的是哪根 net。Tessent 这里显示的是 quick-synth 的门,slang 给不了(门级=独立 yosys 项目)。

修法:改成紧凑符号 + net 名 + file:line,视觉上让位于模块盒子。

03三个方案

方案内容解决代价 / 风险
A · 最小修补 画 pin 名 + FIXED_ORDER 固定 pin 顺序 问题 ①② 最小;但 always/assign 仍是误导性大框
B · Tessent 风格 ★推荐 A + 行为级源头改紧凑符号(端口→箭头符号、logic→小标签块,带 net 名与 file:line)+ 连线显示 net 名 + 视觉层级(实例盒子为主体) 问题 ①②③ 中等;纯渲染层改动,数据已齐(netName / busLabel / loc 都在图模型里)
C · B + 布局稳定 B + ELK interactive 模式钉住已有盒子坐标,追线时老盒子不动 ①②③ + 盒子跳动 ELK interactive 调参有不确定性;设计文档本来就把它列为后期打磨

04待你确认

pin 名字常显(Tessent 式,盒子内侧),还是 hover 才显示?
默认:常显。盒子尺寸公式本来就按标签预留了空间。
连线上要不要显示 net 名?
默认:显示(driver 侧线段上方,9px 灰字)。嫌乱可后续加开关。
行为级源头:紧凑符号(带 net 名 + file:line,可双击开 HDL),还是干脆折叠成 pin 上的一个小标记(最干净但丢信息)?
默认:紧凑符号。输入端口 → 扁箭头符号;always/assign → 小标签块。双击开 HDL 保留。
方案 C 的布局稳定(追线时老盒子不动)这期做吗?
默认:这期不做,pin 顺序固定后最大的困惑已消除;C 列为下一期。
范围确认:bus 折叠、inout 归右、菱形交互(绿=fanin/橙=fanout/灰=已展开/空心=无驱动)均保持现状?
默认:保持。本期只动"怎么画",不动 trace 语义。
