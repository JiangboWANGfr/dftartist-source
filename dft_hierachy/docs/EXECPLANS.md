# 执行计划（ExecPlan）

## 何时需要

修改涉及三个及以上模块、公共契约或数据迁移时，在实现前创建 `docs/plans/<主题>.md`。覆盖多个里程碑的工作按可独立验收的增量推进，不靠一个大提交一次交付。简单修复可在 REVIEW_LOG 简述，不强制新增文件。

计划是执行记录，不取代 DESIGN、REVIEW_LOG 或 B 的 oracle。通常不增加用户批准环节；只有未决定的范围/破坏性变更确需用户选择时才提出具体问题。已授权路线内继续实施。

## 最小内容

1. **目标与验收**：可观察的行为；所依据的 DESIGN 章节和已决定范围。
2. **基线与调用链**：分支/head、已有修改、当前实际层次、尚未实现的层。
3. **修改点**：模块与职责；哪些前序里程碑代码必须变化及原因。
4. **公共契约与兼容**：调用/字段/枚举/默认值/错误/序列化、ABI、旧工程格式的逐项影响；版本或迁移方案；不适用的项也说明原因。
5. **执行步骤**：最小纵向链 → 边界与错误 → 回归 → 完整验证；重构和功能变化区分。
6. **验证**：命令、预期、B 冻结点、运行环境及结果记录；不可执行项的明确原因。
7. **风险、回退与待决项**：资源/取消/数据丢失/兼容风险，如何恢复；标出需要 B/C 或用户决定的真实事项。
8. **进度与交接**：完成项、实际提交/证据、剩余项。阶段未完成时不可把整份计划标完成。

## 模板

```markdown
# <主题>

## 目标与验收

需求、验收场景、DESIGN 章节、范围决定。

## 基线与调用链

实现 head / 测试 head / 契约 SHA；已有修改如何保护；实际调用链。

## 修改点与前序代码

模块、职责、旧行为和变化原因。

## 契约与兼容

公共 API/ABI、IPC、Schema、配置/插件、工程文件逐项影响及处理。

## 执行步骤

- [ ] 最小纵向链
- [ ] 错误、取消、边界、兼容
- [ ] 受影响回归
- [ ] 全量构建与本阶段验收

## 验证记录

| 日期/head | 命令/目录 | 退出码与断言摘要 | 环境/日志 | 结论边界 |
|---|---|---|---|---|

## 风险、回退、待决事项

具体失败模式、恢复办法、决定归属。

## 进度与交接

完成项/提交；剩余项；B 验证重点；C 审查重点。
```

新增稳定架构决策回写 DESIGN；评审和用户决定追加 REVIEW_LOG。计划只链接这些来源，避免一项决定在三个文件内各自演进。
