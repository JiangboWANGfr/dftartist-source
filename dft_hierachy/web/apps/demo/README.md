# Hierarchy demo

同仓库固定布局 Electron 宿主，组合树、源码、属性和原理图等现有视图。
契约见 `docs/DESIGN.md` §6.27–6.33，实施记录见 `docs/plans/M5-demo-shell-production.md`
及 `docs/plans/M6-combined-demo.md`。这是开发演示壳，Studio 集成仍另行推进。

在仓库根目录运行：

```sh
npm --prefix web run demo
# 或使用自有 Core 构建：
HIER_BIN=/absolute/path/to/hier npm --prefix web run demo
```

先构建 `core/build/hier`，并按现有项目说明安装 web 依赖/Electron。
选择 HDL 文件或文件列表；顶层名可留空。文件列表使用 Core 的 `-F` 相对路径语义。
取消选文件保留当前设计。更换设计或关闭时，旧模型和 SDK 被释放，
main 等待旧进程退出后才允许启动新进程。

树只初始加载 roots。点击对象后显示所属实例属性与定义源码；
port/signal 的连接沿原模型展示。搜索和路径按输入原文显式提交，
选择定义后可在定义实例中选择 occurrence。源码双击定位候选，
确认候选保留当前源码文档。保留文档的目标与当前选择不同时，源码范围显示
“当前文档（保留）”；明确选择范围后加载当前目标，即使仍选择“定义”也可更新。
“刷新源码”刷新当前文档。范围不自动回退，确认候选不自动加载新目标。
请求进行时，同一按钮变为“取消源码请求”；完成或取消后恢复“刷新源码”，可以明确重试。
未加载任何源码目标时按钮禁用。切换按钮文字保留键盘焦点，完整状态和错误仍在源码区显示。

右侧使用“实例属性 / 对象连接 / 搜索结果 / 定义实例 / 路径结果”标签，方向键及 Home/End 可切换。
端口查询提示缺少 side 时，在“对象连接”的“连接侧”中明确选择内部或外部即可重新查询。
此操作只改变连接查询侧，保留查询位段、源码和当前选择；选择其它对象后使用新目标自己的侧。
顶层端口仅支持内部侧，信号不指定侧；不适用的侧由 Core 返回原始错误。
阶段和提示一起更新；页面重载或销毁后，旧打开流程不会继续取得新会话或挂载旧面板。
顶部“设计状态”显示会话生命周期；“最近一次操作提示”记录最近的命令错误，可手动关闭。
关闭提示不清除面板中的当前错误，也不修改查询或选择；其它查询成功不会自动清掉这条历史提示。
组件按钮的命令错误及宿主同步错误使用同一提示入口，图工作区不另存一份历史错误。
连续追踪、取消、清除或收图只撤销旧追踪的报告资格，旧取消不会盖成当前操作错误。
当前追踪失败仍显示原Core原因，明确重试成功保留已有提示；外部示例发布不影响当前追踪报告。
同一文档的源码位置绑定不因表单、侧栏或窗口尺寸重绘而重建；切换文档仍会撤销旧位置反馈。
搜索或路径提交后显示相应结果，“收起查询结果”返回对象详情且保留查询。源码候选在明确查询时展开，
可以收起；再次查询同一位置也会重新展开，不自动确认候选。
打开原理图后以图为主区；顶部“源码 / 原理图 / 双视图”切换显示，保留源码文档、候选和图结果。
切换显示不会重新追踪、布局或取消在途任务。“收起原理图”卸载图工作区后取消在途追踪、
布局和分组查询，回收原生 Worker；关闭设计才最终释放图模型和整个会话。
已完成图成员保持，再次显示不自动追踪或布局；新建显示投影仍需匹配自己的布局结果。
布局取消及原任务的清理错误（含嵌套原因）显示在最近操作提示中，不因视图卸载而丢失。
焦点在已展开的高级控制或来源详情内容区内时，普通 Escape 只收起该区并返回对应入口。
入口按钮自身及其它工具栏控件上的 Escape 不收起面板；在入口上按 Enter/Space 切换展开状态。
详情沿用原视图的 Tab 顺序；有溢出时可进入浏览器可聚焦的滚动区，空的非溢出区不增加 Tab 停靠点。
输入法组合或子控件已处理的 Escape 保留当前面板和焦点。

## 构建与验证

### 追踪与原理图

1. 点击“显示原理图”，在实例属性中选择一个端口，或通过已有搜索/源码候选明确选择信号。
2. 检查 lsb/width（无位段选择时初值 0/1）、端口侧、上游/下游和策略；点击“追踪所选对象”。
   策略、位段和节点上限位于“追踪选项”，演示/标注命令位于“演示与标注”，实例分组位于“分组与折叠”。
   位范围与可追踪性由 Core 校验，失败在来源中可查。端口侧未提供时不替用户猜测。
3. 来源列表保留 complete/partial、原因、frontier 和保守性。演示最多 100 节点、200 边、
   20 层、1000 ms；节点上限可调低。此为演示查询策略，不是 M7 性能承诺。
4. 点击“布局”加载同源 ELK Worker；失败可重试，在途可取消，期限 15 秒。
   追踪/来源/折叠改变后明确重新布局，图与树、源码共用选择。
5. “追踪显示组”只是把当前设计图成员归为一个可折叠显示组，不推导真实实例层级。
   折叠后仍可查全部原成员及内边，多对象选择不会隐式挑选唯一源码目标。
   也可点击“按所属实例分组”：从 Core 读取当前图对象的直接所属实例，再分别折叠实例。
   无对象引用的节点留在组外；这不是整个设计的递归层级浏览器。
   “追踪边束”把设计边按有向显示端点捆束，可与实例折叠组合；每条原边及位段仍可在详情查看，
   不表示这些边是同一电气总线。展开全部组恢复原图。分组查询可取消，失败显示诊断并可再次查询；
   图来源变化后旧分组失效，需重新获取。“使用追踪显示组”恢复默认分组。
6. “添加外部示例”提供映射当前对象的节点、无设计引用节点和示例连接，来源明确为 plan。
   “移除外部示例”不清除 trace；“标注所选对象”替换同一手动标注层，树和图按原引用展示。
   这些是宿主组合示例，不包含 DFT 分析算法。关闭/换设计清理全部模型、Worker 和 SDK。

### 仓库外运行

```sh
npm --prefix web run pack:demo -- --output /absolute/new-demo-directory
cd /absolute/new-demo-directory
HIER_BIN=/absolute/path/to/hier npm start
```

输出目录须尚不存在且位于仓库外。命令打包四个版本化 `@hier` tarball，
在输出目录普通安装现有锁定依赖，严格编译公开声明并构建同一份 app。
四包从当前源码在本次输出内独占暂存、干净编译；不读取或改写共享 dist/
增量编译缓存，过时输出不会进入 tarball。编译依赖借用现有安装，四包解析留在暂存内。
打包成功后移除暂存和其工具链接，交付不包含增量编译缓存。
ELK 0.12.0 Worker 与许可证由同一资产构建程序原样放入 viewmodel tarball，
再从安装后的包复制到 app/dist；CSP 只允许同源 Worker，无 blob/unsafe-eval 放宽。
无 workspace 链接或源码 alias；`delivery.json` 记录 tarball/产物 hash、版本和解析位置，
`dependencies.json` 保存实际依赖树。失败返回非零并保留目录，不覆盖已有交付。

npm 安装采用离线缓存，须已具备现有依赖；Electron 使用其官方安装脚本，
优先使用本机缓存，缓存缺失时可能下载运行时。此目录可在当前平台用 Node 24 运行，
不包含 Core 或设计输入，不是签名安装包或跨平台发行。`HIER_BIN` 必须指向
兼容的 Core（protocol 2 / schema 7）；需要修改 app 时回本仓库维护再重新打包。

### processor_core 操作示例

在具备工作区测试设计的机器上：

1. 选择“文件列表”，顶层填写 `processor_core`，打开
   `nx9000/design/processor_core/processor_core.vc`。
2. 点击根查看属性与定义源码，展开根浏览实例。
3. 路径填写 `processor_core.PROCESSOR_1`，点“定位”并明确选择结果；
   等树定位完成后，展开 `PROCESSOR_1`，选择 `frontend_0`。
4. 搜索 `GPIO_2`，在对应实例行选择对象，查看其属性和 `omsp_gpio` 定义。
5. 源码范围选“实例化”，查看 `processor_core.v` 的 `GPIO_2` 实例化范围；
   最后“关闭设计”，等待“设计已关闭”。

设计文件是外部只读输入，不包含在包中。包外运行自测不等于完整 M5 独立验收。

#### 真实设计的追踪、折叠与源码联动

在上述设计已打开后，可按以下步骤演示 M6 的组合流程：

1. 定位 `processor_core.GPIO_2` 并选择结果；在属性中选择 `p1_dout` 端口。
   路径定位会使树加载所需分页并滚动到该实例，无需手动翻过前面的存储器实例。
2. 显示原理图，明确设置内部侧、lsb `0`、width `2`、组合策略。分别执行上游、下游追踪，
   每次点击“布局”；再反向重复这两个操作，核对来源状态和图元详情。
3. 回到上游图，点击“按所属实例分组”。先折叠实例再折叠追踪边束，然后布局；
   查看聚合节点详情中的原成员与内边。全部展开、布局后，再以相反顺序折叠、恢复。
4. 在 `omsp_gpio.v` 定义源码的 `p1_dout` 声明上放置光标，按 `Alt+Enter`，
   或双击该位置。此定义用于多个实例，需在源码候选中明确确认目标；
   可先用属性中的“实例引用”识别 `GPIO_1`，再选择归属该实例的端口候选。
5. 确认候选后，树和属性定位到所选实例，源码仍保留当前文档。
   重新明确追踪侧和位范围后追踪、布局；点击可选择的图节点，核对属性、源码与树的联动。
6. 关闭设计并重新打开，原图和源码候选应清空。

来源是否完整、实际节点及边数以当前只读 RTL 和 Core 返回为准。端口未指定侧时，
连接面板会显示 Core 的诊断；追踪表单的侧仅作用于该次追踪，不修改其他查询。
本演示是有界追踪，不是一次加载整个设计；也不代表跨平台或完整阶段验收。

### Core 资源上限

主进程已按用户确认的首版策略默认启用：打开30秒、取消2秒后强制终止、
采样Core RSS 4 GiB。环境配置可以逐项覆盖；精确文本`off`关闭该项。
例如显式指定同一组值：

```sh
HIER_BIN=/absolute/path/to/hier \
HIER_CORE_OPEN_TIMEOUT_MS=30000 \
HIER_CORE_CANCEL_TIMEOUT_MS=2000 \
HIER_CORE_MAX_RSS_BYTES=4294967296 npm start
```

以上命令在包外demo目录执行；仓库内把末尾改为`npm --prefix web run demo`。
配置必须为十进制正整数或`off`，两个时间值最大2147483647ms。预算由主进程固定，renderer不能修改。
三项均设为`off`恢复原演示壳无预算行为；Node包通用工厂缺省仍不启用预算。
打开超时、取消等待超时或RSS超限都会结束当前Core会话，界面显示原因后可重新打开。
握手后会核对Core编译诊断；有顶层也可能存在语义错误，错误设计在清理完成后显示失败并允许重试，
仅有警告时可以正常打开。失败清理尚未结束时保持关闭中，不提前允许再次打开。
“编译诊断”按需展开原错误/警告及文件位置；截断时保留全部计数并明确说明。
取消升级会同时结束该会话的其它查询；不会自动重连或重放旧请求。
已打开的Core意外退出时，宿主卸载旧工作区、释放布局Worker和本地模型，等待主进程清理后显示原错误，
然后可以重新选择设计。若文件选择框仍在等待，会先释放本地资源，再等选择结束后串行清理；
取消选择不会恢复断线的旧设计。明确选择新设计且旧清理成功时可继续打开，断线原因保留在最近操作提示。
清理异常会保留诊断并阻止本次替换；不会自动重新打开或重放查询。
输入变化检查使用同一个检查/取消按钮，任务结束后可在原位置继续检查；不会因移除取消按钮而丢失操作焦点。
选择框等待期间不启动新的检查，已有检查仍可取消。焦点事件突发合并到当前检查，不排队或自动重试，
取消/失败保留上次Core观察，检查不重编译或重读当前源码。
工作区组件无法渲染时，顶部打开/关闭入口和设计状态会保留。宿主释放该设计的模型、布局Worker及Core，
显示原始错误和清理原因，清理结束后可明确重新选择设计。选择框尚未结束时先本地释放、再串行清理，
取消选择不会复活故障工作区；合法替换完成后仍可查看原故障提示。此保护限工作区渲染/生命周期错误，
普通操作错误继续使用原命令提示，不自动重试或重放查询。
宿主错误提示保留聚合原因；深原因链使用非递归遍历。异常字段本身无法读取时，会显示明确退化提示，
继续呈现可读原因，并在console保留原异常及诊断检查失败的身份。清理结算后仍可明确重开；
旧会话诊断不会覆盖新操作。此处理不限制错误原因数量，也不承诺任意恶意属性执行或内存耗尽可恢复。
主进程请求关闭资源时即使close同步报错，也会继续等待原Core退出结算；等待中不会提前启用重新打开，
结束后展示原关闭/退出原因并允许明确重开，替换设计遇旧清理失败不会继续启动新Core。
窗口失效和应用shutdown共用同一清理责任；不会用错误返回代替实际退出等待或隐式重试。
RSS限制目前支持macOS/Linux，其它平台可显式关闭RSS；100ms加探测时间采样，
瞬时峰值和renderer/Worker内存不计入。
定时器与进程回收受事件循环/OS调度影响，不承诺物理终止严格早于配置时刻。

排查打开/关闭问题时，启动终端输出的`[hier-demo-design]`记录包含host/renderer、文档/操作代次和
有限阶段名，可区分picker、进程启动、握手、诊断、挂载和退出等待。记录不包含路径、RTL、token或
错误载荷；错误详情仍显示在原操作区域。main只转发本窗口批准主文档的有效记录，不持久保存日志。

Node包消费者可直接传`createProcessTransport({command,args,resourceLimits:{
openTimeoutMillis,cancelTimeoutMillis,maxRssBytes}})`。错误保留
`transport_closed/origin=transport`与`data.reason`（`open_timeout`、`cancel_timeout`、
`memory_limit`、`resource_monitor_failed`），通过原Electron桥显示。

### 仓库内构建和回归

```sh
npm --prefix web run build:demo
npm --prefix web run test:independent:m5:demo
HIER_BIN=/absolute/path/to/hier npm --prefix web run test:demo-graph
# 已打包目录使用同一 A 冒烟（测试工具仍由仓库提供，产品只读包外安装）：
HIER_BIN=/absolute/path/to/hier HIER_A_DEMO_DELIVERY=/absolute/new-demo-directory \
  node --test --test-concurrency=1 web/tests/demo-graph*.test.mjs
```

产物 `dist/main.mjs`、`dist/preload.cjs`、`dist/renderer.js` 和 CSS 位于本 app。
app 控制桥声明为 `dist/types/bridge.d.ts`；原通用包出口保持。
构建核 renderer 没有 Node/Electron 主进程依赖，只有一个 React 实例。
标准测试入口执行 B73 原生产类型、设施/Core 控制与真实 Electron 集合。
执行结果与设施缺口以 REVIEW_LOG 的实际证据为准，不以脚本存在推断通过。

renderer 仅取得 `hierDemo` 和原 `hierBridge` 的固定能力；无路径/启动命令/
任意 IPC。main/preload 使用现有 Electron，renderer 仅组合 SDK、模型和视图。
没有会话保存、旧工程导入、数据迁移或 DFT 业务实现。

工作区空间整理：

- 设计信息显示Core打开时间，查询结果基于打开时的版本。“检查输入变化”或窗口重新获得焦点时
  检查已记录的输入；正在打开/关闭时不自动检查，重复触发合并到同一任务，可显式取消。
  检查不重新编译、不重读源码或移动选择；文件变化需通过“打开设计”重新选择并加载。
  失败/取消保留上次完成的结果并说明状态。输入摘要/检查范围不完整时警告常驻，不能据“未发现变化”
  断言表外include/库未变。变化的FileRef作为不透明引用显示，最多显示前100项并保留完整变化总数。

- 工作区工具栏集中视图、侧栏和原理图入口。“查询工具”收起/展开搜索与路径表单；默认展开。
  收起保留输入原文、结果和选择；展开聚焦搜索，表单内按Escape返回工具栏。错误提示保持可见。
- “导航”“详情”可以收起左右侧栏；搜索/路径提交会打开结果所在侧栏。
- 连续搜索、定位或切换连接侧时，旧查询的取消不会冒作当前失败；明确取消仍在原结果区显示。
  当前失败保留统一提示，成功查询不会清除已有历史提示。
- 连续选择以最后一次选择更新属性、连接和源码；清空或多选会清除单目标详情。
  模型通知中的选择和明确源码动作在通知结束后协调，源码候选确认继续保留当前文档与候选。
- 拖动两侧分隔线调整导航/详情宽度；聚焦分隔线后，左右方向键移动边界，Home/End移至可用边界，
  Enter或双击恢复默认。拖动中按Escape取消。窗口缩小时会限制侧栏宽度；放大后恢复所选宽度。
  收起再展开保留宽度，关闭或更换设计后重置；不保存到磁盘。
- “双视图”在宽主区左右并排，在窄主区上下排列；收起侧栏可以增加主区宽度，已有源码和图布局保持。
  拖动图与源码之间的分隔条分配空间；方向键按排列方向移动，Home/End至边界，Enter/双击复原，Escape取消拖动。
  两种排列分别保留本设计中的尺寸偏好，窗口缩小时限制实际尺寸，恢复空间后恢复；新设计重置。
- 右侧标签换行显示，搜索、定义实例、路径结果入口都可直接看到，仍支持方向键和 Home/End。
- 图画布随窗口和侧栏调整尺寸，视图切换不重新布局；“高级控制”展开位段、预算、演示/标注、分组和说明。
- “来源与详情”展开原来源/图元/标注事实；收起时仍显示任务状态、partial原因及失败摘要。
- 在高级控制内按Escape收起并返回入口；非法隐藏参数会自动展开供校验。
- 键盘确认搜索/路径结果或收起结果后，焦点转交当前详情标签；外部输入焦点保持。
- 打开/追踪使用强调按钮，当前视图和详情标签以底线、字重标识；面板标题、表格和状态采用统一视觉层级。
  候选区保留收展标题、状态与操作，去除重复标题；原错误文本和键盘焦点保持可见。
- 拖动候选区上边界可调整列表高度；聚焦分隔条后用上下方向键/Home/End调整，Enter或双击恢复默认，Escape取消拖动。
  收起再展开保留高度偏好，窗口缩小时限制实际高度，放大后恢复；更换设计重置，不保存到磁盘。
- 取消拖动会保留原尺寸偏好或响应式默认，窗口受限时取消也不丢失原宽度/高度。
  隐藏对应区域或双视图换轴会撤销未完成拖动；输入法组合中和已消费的键盘事件不调整尺寸。

分组查询仅在图视图挂载期间持有任务；取消/失败保留当前图的上次分组，使用追踪显示组或图改变时撤销。
分组失败显示完整可读原因；清除、取消或新查询不会被旧诊断覆盖。普通视图切换保留任务，显式收起原理图取消分组，重新显示时不会自动查询。

最近操作提示在诊断格式化完成后再次核对原操作资格；清除或替换同一查询后，不会由旧错误重新写入。
诊断期间收到更新的组件错误时保留更新提示；其它查询成功不清除已有历史，关闭提示也不改变模型结果或错误。
